배포와 업데이트.

ClipFin은 Windows 11 x64를 기본으로 하며 Windows 10 x64도 지원합니다. 무료로 다운로드할 수 있습니다. 공식 배포 파일은 GitHub Releases의 ClipFin-버전-win-x64.zip입니다. ZIP 안의 단일 EXE를 실행합니다. 프로그램 소스는 비공개로 관리합니다.

업데이트 순서

  1. 시작할 때와 4시간마다 새 버전 정보를 확인합니다.
  2. 상단 업데이트 알림을 누르면 ZIP 다운로드·검증을 진행합니다.
  3. 다운로드 완료 후 바로 진행 / 닫으면 진행을 선택합니다. 창의 X/ESC로 선택을 미룰 수 있습니다.
  4. ‘닫으면 진행’은 트레이로 숨기기가 아닌 실제 프로그램 종료에 적용합니다.
  5. 복제한 updater가 원본 EXE를 백업하고 새 EXE를 압축 해제·검증·재실행합니다. 진행률 창으로 단계를 안내합니다.
  6. 파일 오류나 새 프로그램 시작 실패에는 원본 복구를 시도합니다.

파일과 검증

같은 버전의 배포 파일을 바꿔 끼우지 않습니다. ZIP 크기와 SHA-256, ECDSA P-256 배포 서명을 확인하며 EXE의 x64·버전도 검사합니다. 업데이트 서명은 Windows Authenticode 인증서 서명과는 별개입니다. GitHub 연결이 차단된 환경에서는 수동 다운로드를 이용할 수 있습니다.

내 자료는 그대로

업데이트는 프로그램 EXE와 전용 작업 폴더를 대상으로 합니다. 수신 자료는 교체하지 않습니다. 1.0.1은 기존 대화·설정·별칭을 보존하면서 DPAPI 보호 형식으로 변환합니다. 변환 후 1.0 프로그램으로 되돌려 사용하지 마세요. 즉시 업데이트하면 현재 전송이 중단될 수 있습니다. 백업과 작업 기록은 복구를 위해 보존합니다. 전원 차단으로 설치가 끊겼다면 최근 .bak 파일을 ClipFin.exe로 복원할 수 있습니다.

공유와 개인정보

공유 파일은 보내는 PC에서 직접 전달되며 클라우드 저장 서버로 업로드하지 않습니다. 파일 공유는 기존 HTTP를 사용합니다. 1.0.1부터 프로그램 간 메시지는 TLS 1.3으로 암호화하며 최초에 양쪽 PC의 확인 코드를 비교·승인해야 합니다. 로컬 대화·설정은 현재 사용자 DPAPI, 기기 개인키는 Windows CNG로 보호합니다. 양쪽 앱을 업데이트하고 기존 상대도 파일 수신으로 다시 등록해 주세요. 인증서 변경은 자동 승인하지 않으며 구버전 평문으로 전환하지 않습니다. 기업·기관의 네트워크와 보안 정책에 맞는 환경에서 사용하세요. 이 페이지는 공유 파일·대화·사용자 정보를 수집하지 않으며 분석·광고 스크립트를 사용하지 않습니다.

Android APK

Android는 별도 서명 릴리스 APK와 android/version.json으로 배포합니다. 새 APK의 게시자 manifest 서명·해시·패키지명·버전 코드·설치된 앱과 같은 서명 인증서를 확인하고 Android 설치 화면에서 사용자가 승인합니다. 같은 키로 업데이트하면 대화·설정을 유지합니다. Android 15 에뮬레이터에서 Windows와 실제 상호 운용 및 상위 APK 설치·자료 보존을 검증했으며, 휴대폰과 사내 Wi-Fi/MDM 환경은 현장 확인이 필요합니다. 백그라운드 클립보드 감시 대신 공유 메뉴·화면에서의 붙여넣기를 사용합니다.

English summary

Free download for Windows 11 x64, with Windows 10 x64 support. Official immutable release ZIPs contain one executable. The app checks for updates at launch and every four hours; clicking the notice downloads and verifies the package before offering “Update now” or “When I quit.” Hiding to tray is not quitting. A copied updater backs up the EXE, extracts and validates the new version, confirms startup, and attempts rollback on failure. User settings and received files are separate. Update signatures are distinct from Windows Authenticode signing. Both peers must be online for direct messages. File sharing still uses HTTP. From 1.0.1, messages use TLS 1.3 with mutual device certificates. Compare the verification code on both PCs before messaging. Both apps need updating and encrypted re-pairing. Local records use current-user DPAPI; nonexportable private keys stay in Windows CNG. Certificate changes and plaintext fallback are refused. Protected records cannot be read by the older 1.0 app.
